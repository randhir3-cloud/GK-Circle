# Documentation Rules

- Documentation must match implemented behavior and the actual Go/Nuxt architecture.
- Do not claim that planned PCS, AI, creator, mobile, or analytics capabilities are implemented.
- Keep operational commands executable and free of secrets.
- Preserve licence and upstream attribution.
- Update README, architecture, deployment, and affected feature documentation when behavior changes.
- Store evidence and reports under `docs/`, not the repository root.
- Mark legacy or future material clearly so it cannot be mistaken for current functionality.
